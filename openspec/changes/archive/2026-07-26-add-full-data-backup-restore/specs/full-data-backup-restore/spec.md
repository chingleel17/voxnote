## ADDED Requirements

### Requirement: 使用者可以建立可攜式完整資料備份
系統 SHALL 允許使用者從設定頁選擇備份 ZIP 的儲存位置。備份 SHALL 包含所有會議相關結構化資料、分類、標籤、會議範本、常用參與者、錄音檔與封存目錄，並以版本化 manifest 和相對資產路徑描述內容。manifest MUST 包含格式版本、來源應用程式版本、資料庫 schema revision 及資產對應。備份 MUST NOT 包含 API 金鑰、供應商憑證、模型檔或裝置專屬設定。系統 MUST 先建立同層暫存 ZIP，僅在完整寫入及關閉成功後才取代使用者選擇的檔案。

#### Scenario: 成功建立包含錄音的備份
- **WHEN** 使用者選擇儲存位置並確認建立完整備份
- **THEN** 系統建立可開啟的 ZIP，內含資料庫快照、manifest 與每個已存在錄音檔的相對資產檔案

#### Scenario: 錄音檔遺失時建立備份
- **WHEN** 備份資料庫中的錄音路徑指向不存在或無法讀取的檔案
- **THEN** 系統仍建立包含其餘資料的備份，並在完成結果列出遺失或無法讀取的檔案

#### Scenario: 建立備份失敗時保留既有檔案
- **WHEN** 備份 ZIP 寫入中斷或寫入失敗且目標位置已有同名備份
- **THEN** 系統移除暫存檔、保留既有備份檔且顯示失敗結果

### Requirement: 備份必須保留資料庫一致性
系統 SHALL 在建立 ZIP 前產生 SQLite 一致性快照，而非直接複製正在使用中的主資料庫檔。備份內不得要求 `voxnote.db-wal` 或 `voxnote.db-shm` 才能讀取會議資料。

#### Scenario: 資料庫使用 WAL 時建立備份
- **WHEN** 使用者在 VoxNote 執行期間建立備份且資料庫存在尚未 checkpoint 的 WAL 資料
- **THEN** 備份資料庫快照包含該次匯出開始時所有已提交的資料

### Requirement: 使用者可以預檢備份並選擇匯入模式
系統 SHALL 允許使用者選擇 VoxNote 備份 ZIP，並在變更本機資料前驗證 manifest 格式與支援的 schema revision、SQLite 快照完整性及外鍵、資產項目、安全 ZIP 路徑、檔案數量、解壓大小及目標可用空間。系統 MUST 拒絕絕對路徑、路徑穿越、符號連結或重複 ZIP 項目。驗證通過後，系統 SHALL 顯示備份建立時間、資料筆數、資產數量、警告與可選的「合併」或「覆蓋」模式；執行匯入前 MUST 要求使用者確認。

#### Scenario: 選擇有效備份
- **WHEN** 使用者選擇格式相容且內容完整的 VoxNote 備份 ZIP
- **THEN** 系統顯示可匯入的資料摘要及匯入模式選項，且尚未修改本機資料

#### Scenario: 選擇無效或不相容備份
- **WHEN** 使用者選擇缺少必要項目、含不安全 ZIP 路徑或格式版本較新的備份
- **THEN** 系統拒絕匯入、顯示可處理的錯誤訊息，且不修改本機資料或檔案

### Requirement: 覆蓋還原會完整取代現有 VoxNote 資料
系統 SHALL 在使用者確認覆蓋模式後，以備份中的資料取代目前受 VoxNote 管理的結構化資料、錄音與封存資產。系統 MUST 將每個還原的錄音和封存路徑重寫為目前電腦的應用程式資料目錄，且不得保留來源電腦的絕對使用者路徑。錄音目標檔名 MUST 包含 recording UUID，以避免同名檔案覆寫。系統僅可置換 AppData 內受管理的 `recordings` 與 `archives` 目錄，MUST NOT 刪除使用者設定的外部儲存目錄內容。若還原未成功，系統 MUST 保留還原開始前的資料與資產。

#### Scenario: 還原至不同 Windows 使用者帳號
- **WHEN** 使用者以覆蓋模式匯入由另一個 Windows 使用者帳號建立的備份
- **THEN** 匯入的錄音與封存會議可在目前帳號下開啟，且資料庫不再引用來源帳號的檔案路徑

#### Scenario: 覆蓋還原失敗
- **WHEN** 覆蓋還原在資料庫寫入或資產交換期間發生錯誤
- **THEN** 系統回報失敗並維持匯入前的資料庫內容與受管理資產

### Requirement: 合併匯入不得覆寫既有會議資料
系統 SHALL 在使用者確認合併模式後，只新增目標資料庫中不存在的 UUID 資料。UUID 已存在的會議、逐字稿、摘要、錄音、範本與說話者對應 MUST 保持不變並列為略過項目。分類與標籤 MUST 依名稱重用既有資料；常用參與者 MUST 依名稱保留較高的使用次數。系統 SHALL 在完成後回報新增、略過、重用與警告的數量。

#### Scenario: 合併含有既有會議的備份
- **WHEN** 使用者以合併模式匯入包含與本機相同會議 UUID 的備份
- **THEN** 系統不覆寫本機會議及其關聯資料，並在結果中計入略過項目

#### Scenario: 合併使用既有分類與標籤的會議
- **WHEN** 備份中的新會議引用名稱與本機相同的分類或標籤
- **THEN** 系統將新會議關聯至本機既有的分類或標籤，而不建立重複名稱資料

### Requirement: 匯入必須與其他資料修改操作互斥
系統 MUST 在執行合併或覆蓋匯入前取得全域資料操作鎖定，並在匯入完成或失敗前持有該鎖定。系統 SHALL 等待已開始的資料修改工作結束，並在鎖定期間拒絕新的會議、錄音、轉錄、校稿、摘要及封存資料修改操作，不得留下部分匯入狀態。

#### Scenario: 匯入期間嘗試建立會議
- **WHEN** 匯入正在執行且使用者或背景工作嘗試建立或修改會議資料
- **THEN** 系統拒絕該操作並顯示資料還原進行中的可處理訊息

#### Scenario: 匯入後解除鎖定
- **WHEN** 匯入成功或失敗
- **THEN** 系統解除資料操作鎖定，後續資料修改操作可正常執行

### Requirement: 匯入結果必須可理解且不暴露敏感資料
系統 SHALL 在匯出與匯入結束後顯示成功或失敗狀態、處理數量、略過數量與警告摘要。錯誤與結果訊息 MUST NOT 顯示 API 金鑰、供應商憑證或其任何片段。

#### Scenario: 顯示匯入完成結果
- **WHEN** 匯入程序完成且部分資產無法還原
- **THEN** 系統顯示新增、略過與警告數量，並說明缺失資產不會阻止其他資料使用

#### Scenario: 匯入成功後更新畫面資料
- **WHEN** 合併或覆蓋匯入成功
- **THEN** 系統重新取得或重新載入目前畫面資料，使會議清單與詳情反映匯入後結果

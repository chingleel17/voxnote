## Why

`server/app.py` 的詞級強制對齊失敗時，程式碼僅寫入 log warning 便繼續執行，語者標籤照常輸出（`app.py:368-377`）。但語者分離依賴詞級時間戳把 pyannote 的語者區間對應到文字；對齊未完成時，`whisperx.assign_word_speakers` 只能以分段層級的粗略時間比對，產出的講者標籤明顯較不可靠。

問題在於這個降級狀態**只存在於伺服器端的 log**。回傳給 Rust app 的 JSON 與正常情況完全相同，前端無從得知這批標籤可信度較低，使用者看到的講者 A／B／C 與對齊成功時外觀一致。結果是使用者對不可靠的結果照單全收，或反過來在標籤正確時仍全篇重新確認——兩種情況都讓校正工作缺少優先順序。

本變更不修復對齊失敗本身（成因多為語言模型缺漏或音訊品質，屬另一議題），而是讓已知的降級狀態能傳達到使用者眼前，使其能快速判斷哪些錄音段落的語者標籤需要人工確認。

## What Changes

- 伺服器轉錄回應新增語者分離品質欄位，標示該次結果是否在詞級對齊完成的前提下產生。
- 非同步任務結果與同步轉錄回應皆包含此欄位，維持既有的兩種模式輸出格式一致性。
- Rust ASR 客戶端解析該欄位並隨轉錄結果保存至錄音段落。
- 會議頁的錄音段落與講者對應區，於語者分離可信度降級時顯示明確提示，指引使用者優先確認該段落的講者標籤。
- 未啟用語者分離時不顯示任何相關提示。

**不包含**：

- 不修改對齊失敗的處理策略（仍以未對齊結果繼續，不中斷轉錄）。
- 不改動語者標籤本身的產生方式與格式。
- 不提供重新執行對齊或重跑語者分離的操作。
- 不涉及 AssemblyAI 供應商（其為黑箱 API，不暴露對齊狀態）。

## Capabilities

### Modified Capabilities

- `local-asr-server`: 轉錄回應新增語者分離品質標示，並要求 Rust 客戶端保存與前端呈現。

## Design Decisions

### 為何是「品質標示」而非「錯誤」

對齊失敗不是失敗路徑：轉錄文字本身仍然有效且完整，僅語者標籤的可靠度下降。若以錯誤呈現，使用者可能誤以為整份逐字稿不可用而重跑，浪費運算資源。因此 MUST 以品質標示呈現，且 MUST NOT 影響轉錄結果的既有處理流程。

### 欄位設計

回應 MUST 新增布林欄位表示詞級對齊是否完成，且僅在啟用語者分離時具意義。既有回應已有 `diarization_enabled`（`app.py:622`），新欄位與其並列，前端以兩者共同判斷是否顯示提示。

欄位 MUST 為選填並具預設值，使既有客戶端在伺服器尚未更新時不致解析失敗；`LocalServerTranscription` 已以 `#[serde(default)]` 處理選填欄位（`asr/mod.rs:20-25`），沿用同一慣例。

### 為何保存至錄音段落而非僅即時顯示

轉錄為非同步任務，使用者未必在完成當下檢視結果。若僅於轉錄回應中傳遞而不落盤，使用者稍後開啟會議時將看不到提示，功能形同無效。故 MUST 隨錄音段落保存。

### 提示的呈現位置

提示 MUST 出現在使用者實際確認講者的位置——錄音段落與講者對應區——而非僅在轉錄完成通知中一閃而過。目的是讓使用者在校正時知道從哪裡開始，而非事後回想。

## Impact

**修改既有檔案**

- `server/app.py`：`transcribe()` 回傳對齊狀態；`build_transcription_response()` 與非同步任務結果納入新欄位。
- `server/test_app.py`：新增對齊失敗時回應欄位的測試。
- `src-tauri/src/asr/mod.rs`：`LocalServerTranscription` 新增選填欄位並向上傳遞。
- `src-tauri/src/db/mod.rs`：`recordings` 以 `ALTER TABLE` 新增欄位（向下相容，符合既有 migration 慣例）。
- `src-tauri/src/db/models.rs` 與 `src/types/index.ts`：同步 Rust struct 與 TS interface。
- `src/pages/meeting.ts` 與 `src/styles.css`：錄音段落與講者對應區的提示呈現。

**不需修改**

- 語者標籤正規化邏輯（`_to_segments`）：本變更不改動標籤產生方式。
- AssemblyAI 路徑：不暴露對齊狀態，維持現狀。

**相容性**

- 舊版伺服器搭配新版 app：欄位缺漏時視為未降級，不顯示提示，行為與現況一致。
- 新版伺服器搭配舊版 app：多餘欄位被忽略，不影響解析。

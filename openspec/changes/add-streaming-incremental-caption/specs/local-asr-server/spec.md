## ADDED Requirements

### Requirement: 低延遲轉錄端點供增量式呼叫方使用

伺服器 MUST 提供一個專供增量式即時字幕使用的低延遲轉錄端點，使呼叫方能以遠高於批次流程的頻率（每次間隔可短至一秒以下）對持續累積的音訊發出轉錄請求。

該端點 MUST NOT 執行強制對齊（forced alignment）或語者分離等以完整音訊為前提的後處理——此類處理需先有完整的段落邊界，與增量式呼叫的前提相衝突，且會使單次請求的耗時超出即時節奏可接受的範圍。

該端點 MUST 回傳純文字轉錄結果，且其輸出格式 MUST 足以讓呼叫方比對連續兩次請求的結果以判定文字是否穩定。

既有的批次轉錄端點與同步轉錄模式的行為 MUST 完全不受此端點影響。

#### Scenario: 增量式字幕以高頻率呼叫低延遲端點

- **WHEN** 即時字幕以短於一秒的間隔，對持續累積的音訊重複發出低延遲轉錄請求
- **THEN** 系統 MUST 對每次請求回傳當下音訊的轉錄文字，且單次請求的處理 MUST NOT 包含強制對齊或語者分離

#### Scenario: 連續兩次請求的結果可供一致性比對

- **WHEN** 呼叫方對重疊的音訊範圍連續發出兩次低延遲轉錄請求
- **THEN** 兩次回應的文字格式 MUST 一致，使呼叫方能直接比對其共同部分

#### Scenario: 批次端點不受低延遲端點影響

- **WHEN** 低延遲端點與批次轉錄端點於同一服務實例上並存
- **THEN** 批次端點的輸出格式、語者分離與對齊行為 MUST 與新增此端點之前完全一致

#### Scenario: 低延遲端點不可用時的回報

- **WHEN** 低延遲端點因模型未載入或其他原因無法服務
- **THEN** 系統 MUST 明確回報錯誤供呼叫方辨識，MUST NOT 靜默回退至耗時較長的批次路徑而使即時字幕停滯
